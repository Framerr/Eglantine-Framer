# Frameropia v0.0.1 — Patch Notes

*This historical v0.0.1 build predates the full Frameropia application rebrand; its executable may still be labelled Eglantine.*

**First experimental release of this fork, focused on testing Pokémon Pokopia.**
This version is based on Eglantine's `nx2` branch. Features and fixes inherited from upstream are not presented as new work in this fork.

## Changes in this fork

### Graphics and emulation

- **Vulkan — null texel-buffer views:** use `VK_WHOLE_SIZE` instead of a zero-length range when creating a view of the fallback buffer.
- **Vulkan — fallback buffer capabilities:** add `VK_BUFFER_USAGE_UNIFORM_TEXEL_BUFFER_BIT` and `VK_BUFFER_USAGE_STORAGE_TEXEL_BUFFER_BIT` so the fallback buffer can be used with texel-buffer descriptors. ([PR #1](https://github.com/Framerr/Frameropia/pull/1))

### Releases, builds, and maintenance

- Establish the fork's own **0.0.1** version and changelog. ([PR #2](https://github.com/Framerr/Frameropia/pull/2))
- Allow stable releases to be started manually using the `ci` workflow. ([PR #3](https://github.com/Framerr/Frameropia/pull/3))
- Add `fork-preflight` checks for version metadata, release notes, and CI shell scripts on pull requests and pushes to `nx2`. ([PR #5](https://github.com/Framerr/Frameropia/pull/5))
- Add `fork-windows-release` to build and publish Windows test versions using Eglantine's existing workflows. ([PR #6](https://github.com/Framerr/Frameropia/pull/6))
- Remove the inherited `Retarget PRs` workflow, which failed because it expected an `nx2-experimental` branch that does not exist in this fork.
- Add fork-specific patch notes with a plain-English summary. ([PR #7](https://github.com/Framerr/Frameropia/pull/7))

### Testing and issue reporting

- Add a [Pokémon Pokopia testing guide](https://github.com/Framerr/Frameropia/blob/main/docs/POKOPIA_TESTING.md) covering startup, save loading, world geometry, lighting, photos, audio, saving, and performance.
- Add a dedicated [Pokopia bug-report form](https://github.com/Framerr/Frameropia/issues/new/choose), update the README, and document the build and release process. ([PR #4](https://github.com/Framerr/Frameropia/pull/4))
- Remove six unused inherited issue templates, leaving only the Pokopia form and its configuration. ([PR #8](https://github.com/Framerr/Frameropia/pull/8))

## Plain-English summary

**This is the first test version of Frameropia.** We have corrected how the emulator handles certain empty graphics resources. That change makes the graphics code more robust, but it has not yet been shown to fix a specific issue in Pokémon Pokopia.

We have also organised the project so that Windows test builds can be produced, basic checks run automatically before changes are merged, and bugs can be reported using a dedicated form.

**What still needs testing:** whether Pokopia starts reliably, whether furniture and other objects appear correctly, whether photos contain visual artifacts, whether lighting looks right, and how well the game performs. These are targets for future fixes, **not problems we can claim are solved**.

If you find a problem, please include the build version, steps to reproduce it, and a relevant emulator log if available. Check logs for personal information before sharing them.
